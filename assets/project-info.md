# 项目内容补充说明

网站运行时会读取 `assets/portfolio.json`。本文件用于说明如何补充和维护项目内容，方便后续在不修改页面结构的情况下更新作品集。

补充内容时，请始终以真实代码、运行记录、日志或项目文档为依据。页面的重点是说明项目解决了什么问题、使用了哪些技术、本人负责了什么工作，以及当前完成到什么程度。

## 一、建议的补充顺序

1. 先填写个人资料、联系方式和教育信息。
2. 再核对每个项目的实际状态、技术栈和个人贡献。
3. 补充 GitHub 源码地址和项目详情。
4. 最后添加项目封面、演示视频和简历文件。
5. 启动网站并检查桌面端、移动端、链接和媒体回退状态。

## 二、个人信息如何补充

打开 `assets/portfolio.json`，修改 `profile` 和 `education` 字段：

```json
{
  "profile": {
    "name": "你的真实姓名",
    "headline": "Software Developer / Embedded Linux / AI Applications",
    "introduction": "用两到三句话说明你的技术方向和实践重点。",
    "seeking": "软件开发 · 实习机会",
    "github": "https://github.com/你的账号",
    "email": "your-email@example.com",
    "resume": "/files/resume.pdf",
    "resumeAvailable": false,
    "about": [
      "第一段介绍教育背景和关注方向。",
      "第二段介绍已经进行过的后端、Linux、模型部署或系统集成实践。"
    ]
  },
  "education": {
    "university": "中南大学",
    "major": "生物医学工程",
    "degree": "本科",
    "period": "入学时间 / 毕业时间"
  }
}
```

填写规则：

- `name`、`github`、`email` 必须替换为真实信息；没有准备好时可以留空，页面会显示“待补充”。
- `github` 使用完整的 `https://` 地址，不要填写不存在的仓库。
- `email` 只填写实际可接收邮件的地址。
- `period` 在确认日期前保留“待补充”，不要猜测时间。
- 不要把求职目标写成已经获得的职位，也不要添加未经证实的奖项、工作经历或性能指标。

## 三、每个项目需要补充什么

项目数据位于 `assets/portfolio.json` 的 `projects` 数组中。每个项目至少应确认以下内容：

| 字段 | 应填写的内容 |
| --- | --- |
| `title` / `englishTitle` | 中英文项目名称 |
| `summary` | 一句话说明项目解决的问题和实现方式 |
| `status` / `statusType` | 当前真实状态；进行中使用 `progress` |
| `stack` | 实际使用过的技术和设备 |
| `features` | 已完成的核心功能；进行中的项目写当前范围 |
| `contributions` | 本人实际编写、调试、部署或集成的工作 |
| `github` | 可公开访问的源码地址；没有时留空 |
| `overview` | 项目背景、问题和整体方案 |
| `flow` | 从输入到输出的主要技术流程 |
| `implementation` | 按模块说明具体实现 |
| `ownership` | 本人负责内容与第三方依赖的边界 |
| `boundaries` | 当前限制、未验证内容和不能推断的结论 |
| `nextSteps` | 尚未完成、准备继续补充的内容 |

项目描述建议按照下面的逻辑组织：

```text
项目遇到的问题
    -> 使用的技术方案
    -> 本人完成的模块
    -> 当前可验证的结果
    -> 尚未完成或依赖第三方的部分
```

### 项目一：病理图像云分析平台

目前已有资料可以展示：

- Flask 后端 API。
- ZIP 批量上传、项目和图片任务管理。
- Redis 异步任务队列与独立 Worker。
- 用户并发控制、等待队列、任务状态和进度查询。
- 批量任务处理和 Excel 结果导出。

补充时建议提供：

- 关键 API 或模块的源码路径。
- 一次完整任务的实际运行流程和状态变化。
- Worker 如何处理成功、失败和重试。
- 如果有真实测试数据，可补充任务规模和测试条件。

不要把第三方 GLM 多模态接口描述成自己训练的模型，也不要把图片内容描述写成医疗诊断结论。没有性能压测和准确率记录时，不要填写推测数据。

### 项目二：基于 Jetson 的端侧 AI 分析系统

目前已有资料可以展示：

- Jetson Orin Nano、Jetson AGX Thor 和 Ubuntu 环境。
- Docker、Python、FastAPI、Vue、llama.cpp 的集成方向。
- 图像保存、选择、删除和切片会话管理。
- USB 显微镜图像采集、模型调用和流式结果展示。
- 本人负责后端、环境部署、模型适配和前后端联调。

补充时建议明确：

- 每项工作对应的设备型号和运行环境。
- 本人编写的后端文件、接口和集成代码。
- 第三方视觉模型、语言模型和既有 Vue 前端代码的来源。
- 模型量化方法、参数、运行命令和真实测试记录（如果有）。

不要把第三方模型或既有前端代码写成独立开发成果。没有真实量化参数和测试结果时，不要写“性能提升多少”或“延迟降低多少”。

### 项目三：i.MX6ULL 嵌入式 Linux 开发

当前项目状态是“进行中”。已有资料只支持展示以下实践方向：

- i.MX6ULL、ARM、Linux 和 U-Boot。
- 系统配置和启动流程实践。
- LCD 调试和驱动开发方向。

补充完成内容时，请为每项内容提供可核验记录，例如：

- 工具链和构建环境配置。
- U-Boot 或 Linux 启动日志。
- LCD 调试步骤、问题和解决方式。
- 驱动代码路径、测试方式和实际运行结果。

在没有这些记录前，继续使用“进行中”或“待补充”，不要写成“已完成”，也不要上传无法确认来源的运行截图。

## 四、封面和演示视频如何补充

每个项目已经预留媒体路径。当前数据中的 `available` 默认为 `false`，因此素材不存在时不会发起请求，也不会导致页面报错。

| 项目 | 封面路径 | 视频路径 |
| --- | --- | --- |
| 病理图像云分析平台 | `/images/pathology-cover.png` | `/videos/pathology-demo.mp4` |
| Jetson 端侧 AI 系统 | `/images/jetson-cover.png` | `/videos/jetson-demo.mp4` |
| i.MX6ULL | `/images/imx6ull-cover.png` | `/videos/imx6ull-demo.mp4` |

添加素材后，在对应项目中修改：

```json
{
  "cover": {
    "src": "/images/pathology-cover.png",
    "available": true
  },
  "video": {
    "src": "/videos/pathology-demo.mp4",
    "available": true,
    "type": "video/mp4"
  }
}
```

注意事项：

- 封面和视频可以单独启用，不需要同时添加。
- 建议视频长度为 10 到 15 秒，使用浏览器常见的 H.264 MP4 编码。
- 视频不会自动播放，只有用户点击播放按钮后才会创建播放器。
- 播放器默认静音并循环，提供原生控件和静音、循环开关。
- 图片加载失败时会回退到 CSS 占位封面，视频播放失败时会提示并恢复占位状态。
- 不要使用包含个人隐私、未授权项目资料或无法公开的客户数据作为素材。

## 五、源码链接和简历如何补充

项目源码地址在项目的 `github` 字段中：

```json
"github": "https://github.com/你的账号/项目仓库"
```

简历文件放在 `files/resume.pdf`，然后将个人资料中的配置改为：

```json
"resume": "/files/resume.pdf",
"resumeAvailable": true
```

网站会检查文件是否存在并且是否为 PDF。检查失败时会自动恢复为不可下载状态，因此不会出现指向不存在文件的下载链接。

## 六、补充后如何检查

启动网站：

```powershell
python main.py
```

然后打开 `http://127.0.0.1:8000`，依次检查：

1. 首页姓名、简介、GitHub、邮箱和简历按钮。
2. 三个项目的状态、技术标签、核心功能和个人贡献。
3. 分类筛选是否显示正确数量。
4. 项目详情页是否能从首页打开并返回。
5. 320px 左右的手机宽度是否没有横向滚动。
6. 未添加的媒体是否仍显示占位封面。
7. 已添加的视频是否需要点击才播放，且静音、循环开关正常。
8. i.MX6ULL 项目是否仍准确标明“进行中”，除非已有新记录证明完成。

如需运行自动检查：

```powershell
python tests/browser_check.py
```

该检查使用内存模拟播放器，不读取或生成真实项目视频和图片。
